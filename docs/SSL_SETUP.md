# SSL Setup (Local Development)

**This guide is for local development SSL setup only.**

For staging/production SSL with Let's Encrypt, see the [Hubzilla Stack Deployment Guide (Staging)](HUBZILLA-STAGING_DEPLOYMENT.md) and the [Stalwart Mail Stack Deployment Guide](STALWART-SEPARATE-STACK-DEPLOYMENT.md).

---

## Overview

Local development uses **mkcert** to generate browser-trusted SSL certificates for `localhost` and `mail.localhost`. This eliminates browser security warnings during development.

**Production deployments** use Let's Encrypt via Traefik for automatic SSL certificate provisioning and renewal.

---

## Install mkcert

### Linux/WSL
```bash
sudo apt install mkcert
```

### macOS
```bash
brew install mkcert
```

### Windows
Download from: https://github.com/FiloSottile/mkcert/releases

**Important for Windows + WSL2:**
Install mkcert on the Windows host (not in WSL2). This ensures `mkcert -install` adds the Certificate Authority to the Windows certificate store, making Windows browsers trust the certificates.

---

## Setup Certificate Authority

```bash
# Initialize mkcert (creates CA)
# MUST run as Administrator on Windows
mkcert -install
```

This command:
1. Creates a local Certificate Authority (CA)
2. Adds the CA to your system's trusted root certificates
3. Shows a confirmation prompt to add CA to certificate store (Windows)

### Find CA Path

```bash
mkcert -CAROOT
```

Copy this path exactly - you'll need it for the `.env` configuration.

**Common paths:**
- Linux/WSL: `~/.local/share/mkcert`
- macOS: `~/Library/Application Support/mkcert`
- Windows + WSL2: `/mnt/c/Users/USERNAME/AppData/Local/mkcert`

---

## Manual Certificate Import (Windows)

If automatic installation fails on Windows:

1. Press **Win+R** → type `mmc` → Press Enter
2. File → Add/Remove Snap-in
3. Select **Certificates** → Add
4. Choose **Computer account** → Next → Finish
5. Navigate: **Trusted Root Certification Authorities** → **Certificates**
6. Right-click → **All Tasks** → **Import**
7. Browse to mkcert CA path and select `rootCA.pem`
8. Complete the wizard

## Configure Environment

Edit `.env` file in project root:

```bash
# Set MKCERT_PATH to the path from mkcert -CAROOT
MKCERT_PATH=YOUR_PATH_HERE

# Examples:
# MKCERT_PATH=~/.local/share/mkcert                    # Linux/WSL
# MKCERT_PATH=~/Library/Application Support/mkcert     # macOS
# MKCERT_PATH=/mnt/c/Users/USERNAME/AppData/Local/mkcert  # Windows WSL2
```

**Critical:** The path must match exactly what `mkcert -CAROOT` returns.

## How It Works

### Certificate Generation

Traefik automatically generates SSL certificates on first startup:
1. Reads CA certificates from `MKCERT_PATH`
2. Generates certificates for `localhost` and `mail.localhost`
3. Stores certificates in `traefik_certs` volume
4. Configures HTTPS routing

**No manual certificate generation needed.** Just set `MKCERT_PATH` correctly.

### Certificate Trust Chain

```
System Trusted Root CAs
    └── mkcert CA (installed by mkcert -install)
         └── localhost certificate (generated by Traefik)
              └── https://localhost (trusted by browser)
```

Because the mkcert CA is in your system's trusted root certificates, any certificate it signs is automatically trusted.

## Verify Setup

### Check Certificate

1. Start containers: `docker compose up -d`
2. Open: https://localhost
3. Click padlock icon in browser address bar
4. View certificate details

**Should show:**
- Issued to: `localhost`
- Issued by: `mkcert <username>@<hostname>`
- Valid certificate (no browser warnings)

### Check Traefik Logs

```bash
docker logs hubzilla_traefik | grep -i cert
```

Look for successful certificate generation messages.

## Troubleshooting

### SSL Certificate Errors in Browser

**Symptoms:**
- "Your connection is not private" warning
- "NET::ERR_CERT_AUTHORITY_INVALID"

**Solutions:**

1. **Verify mkcert installed:**
   ```bash
   mkcert -CAROOT
   # Should return a path, not an error
   ```

2. **Reinstall CA:**
   ```bash
   mkcert -uninstall
   mkcert -install
   ```

3. **Check MKCERT_PATH in .env:**
   - Must match `mkcert -CAROOT` output exactly
   - No quotes around path
   - Use forward slashes on Windows: `/mnt/c/Users/...`

4. **Restart containers:**
   ```bash
   docker compose down
   docker compose up -d
   ```

### Firefox on Linux

Firefox uses its own certificate store:

```bash
# Install NSS tools
sudo apt install libnss3-tools

# Reinstall mkcert CA
mkcert -uninstall
mkcert -install
```

### Permission Errors

**Windows:** Must run `mkcert -install` as Administrator

**Linux/macOS:** May need `sudo` for system certificate store access

### Path Not Found

**Symptoms:**
- Traefik can't read CA certificates
- Logs show file not found errors

**Solutions:**

1. **Verify volume mount in docker-compose.yml:**
   ```yaml
   volumes:
     - ${MKCERT_PATH}:/mkcert-ca:ro
   ```

2. **Test path is accessible:**
   ```bash
   ls -la "${MKCERT_PATH}"
   # Should show rootCA.pem and rootCA-key.pem
   ```

3. **For WSL2:** Ensure Windows mkcert path is accessible from WSL:
   ```bash
   ls -la /mnt/c/Users/USERNAME/AppData/Local/mkcert
   ```

## Certificate Locations

### On Host System

**CA Certificates:**
- Location: Output of `mkcert -CAROOT`
- Files:
  - `rootCA.pem` - CA certificate
  - `rootCA-key.pem` - CA private key (keep secure)

### In Docker

**Generated certificates:**
- Volume: `traefik_certs`
- Mount: `/certs` in Traefik container
- Files generated automatically by Traefik

## Production SSL

**This mkcert setup is for local development only.**

For staging and production environments:
- **Do not use mkcert**
- **Use Let's Encrypt** via Traefik
- Automatic certificate provisioning and renewal
- Publicly trusted certificates
- No manual CA installation needed

See the [Hubzilla Stack Deployment Guide (Staging)](HUBZILLA-STAGING_DEPLOYMENT.md) and the [Stalwart Mail Stack Deployment Guide](STALWART-SEPARATE-STACK-DEPLOYMENT.md) for production SSL configuration with Traefik and Let's Encrypt.

---

## Security Notes

### Development Only

- mkcert certificates are **only trusted on your machine**
- Not suitable for production use
- Should not be shared between developers
- Each developer runs their own `mkcert -install`

### CA Key Security

The `rootCA-key.pem` file can sign certificates for any domain. Keep it secure:
- Never commit to git
- Don't share between machines
- Regenerate if compromised: `mkcert -uninstall && mkcert -install`
